# Changelog Guidelines

Whenever a new feature is completed:

- Add a new version entry.
- Include the date.
- Group changes by category.
- Keep descriptions short and clear.

Example:

## [v0.2.1] - 05 August 2026

### ✨ Added

- Forgot Password page.
- User profile page.

### 🐞 Fixed

- Login validation issue.
- Navigation bar alignment.

### ♻️ Improved

- Dashboard performance.
- Form validation messages.

# Version Numbering

StudyHub follows Semantic Versioning:

- **Major (1.0.0):** Significant releases with major functionality.
- **Minor (0.2.0):** New features and completed sprints.
- **Patch (0.2.1):** Bug fixes and small improvements.

Examples:

v0.1.0 → Project planning completed.

v0.2.0 → Frontend completed.

v0.3.0 → Backend completed.

v0.4.0 → Database completed.

v0.5.0 → Authentication completed.

v1.0.0 → First complete MVP release.
